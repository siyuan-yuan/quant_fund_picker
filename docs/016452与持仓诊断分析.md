> 分析基于本仓库实际代码与真实缓存数据（2026-08-06 数据快照），所有结论均可复现。
> 修改已落地：`config.SCAN_INCLUDE_OVERSEAS_INDEX`（海外指数QDII通道）+
> 持仓诊断「反推不可靠」⚠ 告警。详见文末「本次改动」。

## 问题一：全部主池扫描后，榜单搜不到 016452，但单基金透视里有

### 结论一句话

**016452（南方纳斯达克100指数发起(QDII)A）的基金类型是「指数型-海外股票」，而扫描池白名单
只放行 A 股四类（偏股/普通股票/指数股票/灵活配置），QDII 基金在所有扫描模式下都被整体排除。**
单基金透视不走池子、直接打分，所以能看到。这不是打分问题——它的分其实很高（S_total≈89，Strong Buy）。

### 证据链（全部在本仓库验证）

| 检查项 | 结果 |
|---|---|
| `cache/fund_meta.csv` 中 016452 的类型 | **指数型-海外股票**（QDII） |
| `cache/rank_all.csv` 中 016452 的近3年 | +69.8%（完整，够主池门槛） |
| 扫描池白名单 `scan_market.TARGET_TYPES` | `{混合型-偏股, 股票型, 指数型-股票, 混合型-灵活}` —— 无「指数型-海外股票」 |
| `output/scan_20260808.csv`（全部主池扫描，4529 只） | 全表 QDII 基金 = **0 只**；`ftype` 只有白名单四类 |
| 单基金透视 `/api/fund/016452` | 正常出分（不经池子，`score_fund` 直通） |
| 引擎对 016452 的归因 | `panel_mode=overseas`，RBSA 正确识别：纳斯达克100 52.5% / 标普500 25.5% / 恒生科技 16.2%，`valuation_blind=True` |

### 被系统性漏掉的范围有多大？

全市场排行表中「指数型-海外股票」共 **169 只**，其中 **91 只近3年完整**（扣除 C/E 份额、去重后
约 **50 只**进入主池）。也就是说「全部主池扫描」此前漏掉了约 50 只被动海外指数基金——
纳指100、标普500、德国DAX、日经225 等全在内。此外 `QDII-普通股票`(57)、`QDII-混合偏股`(83)
等主动 QDII 也被排除（这部分是设计选择，见下）。

### 为什么当初这么设计（合理的动机）

1. **估值盲区**：QDII 没有 A 股式估值分位，`F_value` 天然缺失/降权（README V4.1 已明说
   "估值盲区基金（QDII 等）"）。把它和 A 股基金放在同一把尺子下，估值因子吃亏。
2. **归因面板**：RBSA 面板以 A 股指数为主（12个A股 + 4个境外腿），早期境外腿不完整时
   归因不可信。
3. **交易摩擦**：QDII 申赎确认 T+2~T+3、溢价/暂停申赎常见，执行层（20%移动止损、
   季度再平衡）对它的响应速度不同。

### 但"全部排除"已经过时了（关键事实）

引擎自 V3.3 起就内置了完整的境外支持：境外腿 RBSA（纳指100/标普500/恒指/恒生科技）、
纯境外面板 `panel_mode=overseas`、估值盲区标记 `valuation_blind`。上面的证据显示 016452
的归因完全正常。**扫描白名单只是当年写死时没有同步升级**——所以我把「指数型-海外股票」
（**被动**指数 QDII，基准清晰、风格归因干净）并入了扫描池，主动型 QDII 仍排除
（经理主动选股叠加海外市场，风格归因差，且 `fund_meta` 里其业绩基准五花八门）。

### 本次改动后

- `build_universe(mode="all_main")`：4529 → **4579 只**（+50 只海外指数 QDII）
- 016452 模拟入榜：**S_total = 89.2，Strong Buy 绿灯，榜单第一梯队**
- 开关：`config.SCAN_INCLUDE_OVERSEAS_INDEX = True`（默认开；改 False 即回原行为）

### 使用注意（金融工程师视角的边界）

1. **同榜可比性**：海外指数基金与 A 股基金同榜竞争时，`F_value` 是盲区权重处理
   （016452 的 `val_pct≈0.73` 来自境外腿部分覆盖）。看分时留意 `valuation_blind` 标记，
   不要拿它的「估值分」和 A 股基金直接 PK。
2. **汇率与QDII特有风险**：QDII 还有额度溢价、汇率敞口、T+2 确认延迟——榜单不含这些
   执行层信息，仓位分配时自行折算。
3. 单基透视、持仓批算本来就能查任何基金，只是**榜单**（扫描池）以前漏了这类。

## 问题二：持仓诊断只输入一个总市值，算得准吗？

### 结论一句话

**不准，而且分三层：只输一个市值 → 系统根本算不出回撤（会提示缺入场信息）；
补一个「收益率」让系统反推日期 → 多笔/定投/卖出场景下可能严重低估回撤（实测把 -30.2%
的真实回撤算成 -3.7%，止损形同虚设）；补一个「买入日期」按单笔近似 → 回撤仍有 10pp 级
误差。唯一精确的解法是本系统内置的「操作台账」（每笔买卖 FIFO 核算），输入市值只当锚定。**

### 为什么「只输总市值」不够

持仓诊断输出两件东西：① 单基金 20% 入场高点移动止损；② 组合级 CPPI（HWM→回撤→槽位）。
两者都需要**一条持仓市值的时间序列**，而一条曲线至少要有「什么时候开始持有」才能重建。
只有一个当前市值，等于只知道终点不知道起点——系统返回 `need_entry`（需日期/成本/收益率），
这是正确行为，不是 bug。

### 量化演示：同一持仓，三种输法，三种结果

构造一个真实的「两笔买入 + 中途部分卖出」场景（净值先涨到顶 1.49 再回落到 1.19）：

```
2024-02-19 买 10000   → 2024-05-29 买 10000   → 2024-06-08 卖 5000（部分卖出）
真实（台账 FIFO 核算）：当前市值 14,314.76 | 自高点回撤 -30.2% → 触发20%止损（清仓）
```

| 输入方式 | 系统结果 | 与真实对比 |
|---|---|---|
| 只输总市值 14314.76 | `need_entry`：算不出回撤 | 缺入场信息，止损判断整个缺失 |
| 市值 + 真实总收益率 -5.6% | 反推入场日=2024-06-23，回撤 **-3.7%** → 状态「正常」 | **灾难级低估**：真实 -30.2% 应清仓，系统却说正常 |
| 市值 + 第一笔买入日期 | 回撤 **-20.2%** → 触发清仓（方向碰对） | 仍有 10pp 误差，临界基金（如真实 -19%）会被误分类为「接近/正常」 |
| 台账：三笔操作全记 | 回撤 **-30.2%**，FIFO 成本、份额、曲线全精确 | 基准真值 |

为什么「收益率反推」会差这么多：多笔买入+卖出后，总收益率是一个**现金流加权的混合结果**，
净值曲线上会有多个相距很远的日期满足「从那天持有到现在收益率 = 你的收益率」。
系统按设计取**最晚**的候选（对止损偏保守、不误报），于是把入场点定位在峰值之后——
峰值和回撤整个被跳过。演示里真实的 -30.2% 因此被算成 -3.7%。

### 什么情况下「单笔近似」是够用的

- **一次性买入后从未加仓/减仓**（有明确买入日期）：单笔 = 精确。
- **定投但亏损浅、且你只想要大概水位**：近似可用，但回撤数字别当纪律触发依据。
- **任何有过中途卖出的持仓**：单笔近似基本不可信（份额结构变了，历史曲线形状全错）。

### 比较好的解决方法（按推荐度排序）

1. **用操作台账（推荐，系统已内置）**：`持仓诊断 → 操作台账`，每笔记
   `代码 买/卖 日期 金额`，同一基金任意多笔；卖出按**先进先出**扣成本；全部卖完自动剔除。
   - 系统按「当日复权净值折算份额」逐日重建你**当前剩余持仓**的市值曲线 → 峰值、
     回撤、HWM、CPPI 全部精确；
   - 此时你再填的总市值只用来做**锚定微调**（对齐申赎费/四舍五入差异，`k=市值/计算值`
     整体缩放，持有收益率不变）——曲线形状由台账决定，不取决于你填的数字；
   - 之后每次操作只补记一笔，不用再重输持仓；诊断页的买卖建议有「记入台账」按钮。
2. **至少给出「市值 + 成本金额」**：系统用 `市值/成本-1` 得到真实总收益率，比
   「市值+收益率」多一个校验维度；但入场日期仍是反推的，多笔场景依然要警惕。
3. **支付宝/天天基金导出交易记录**：把每笔买入/卖出按台账格式贴进去，一次性建档，
   之后每月的定投补一条即可——这是定投用户唯一能精确止损的方式。
4. 实在想偷懒：接受「最近一笔近似」的口径（页面曲线图下方已有此说明），
   但**不要把反推出来的回撤当作触发20%清仓的判决依据**。

### 本次改动：系统现在会主动告诉你「算得不可靠」

- `holding_diag.fund_stop_diag`：反推入场日时统计近优候选日期**跨度**，跨度 > 60 天
  （典型的多笔/定投/卖出特征）→ 输出 `infer_ambiguous=True`，`reason` 给出明确提示
  「建议在操作台账记录每笔买卖后重新诊断」；
- 网页持仓表中该行入场日旁显示 **⚠**，悬停可见完整警告；
- 调仓方案的「纪律卖出」理由中也会附加该警告，防止把近似回撤当真触发执行；
- 提供了明确买入日期的用户不受影响（无告警）。

### 进一步的可改进方向（如需实现可另开任务）

1. **份额直输模式**：支持「份额 × 成本单价」直接建档，省去按金额折算的环节；
2. **自动对账**：支付宝/天天基金交易记录文件（CSV）一键导入台账；
3. **多笔锚定**：卖出时允许用户填「到账金额」而非按当日净值折算（现已支持，
   但未来可加费率参数）；当前实现忽略申赎费，金额大时建议在台账金额里扣除费用。
