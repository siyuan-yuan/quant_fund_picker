## 1. 环境与前置

```bash
git clone <repo> && cd quant_fund_picker
git checkout arena/01a05f52-quant-fund-picker
python3 -m venv .venv_review
./.venv_review/bin/pip install -r requirements-v5-lock.txt requests py_mini_racer
```

**数据前置（必须有）**：`cache/nav_*.csv` 15,444 只 + `cache/idx_sh000300.csv` + `cache/fund_meta.csv`。
沙箱内三源不可达，若本机尚无缓存需先抓取（**修正 2026-09-02**：`t0_fetch.py` 没有 `--full-history` 参数，正确用法如下）：

```bash

python t0_fetch.py --start 20060101 --end 20260331      # token: --token / $TUSHARE_TOKEN / cache/tushare_token.txt
# 路径 B：东财/akshare 已清盘基金可得性探针（预登记 #10，覆盖 ≥30% 判"可得"）
python d01_probe_em.py
```

`cache/` 与 `output/` 均被 `.gitignore` 排除，**产物不入库**（纪律 §0.4）。

> **⚠ 关键前置（2026-09-02 补）**：`s61_summarize.py` 以 `output/p1_panel` 为 **CANONICAL 基准**，
> 因此 S6.1 汇总前**必须先在本机构建规范面板**（`python p1_panel_build.py --workers 2`，约 40 分钟，断点续跑）。
> 网格 11 组中**不含** seed0×maxn500（网格为 种子 1–5 × {500,1000} + 全取），故不能拿网格组替代基准。

## 2. 一键入口


直接调用脚本亦可：
```bash

python r35_rebuild_zoo_cache.py --workers 8              # 新增 --workers N（月级并行）
```

**新增两条 lane（2026-09-02）**：
- `parity` —— **跨机一致性闸门**（跑 `build_navadj.py` 再与权威值逐项对账，约 1 分钟），见 §7.2；

## 5. 纪律（本机执行同样受约束）

1. **口径标签**：本批产物一律 **SURV-ADJ**。任何绝对收益/IC/胜率数字对外引用必须带标，
   **不得**冒充 FULL-PIT（U4/A5 未解锁）。
2. **不作采纳裁决**：S6.1 是"仅报告、不平判"（#33 自封）；即便组间离散度大到足以动摇既有结论，
   也只登记为**稳健性告警**，不得据此改门或改模型。
3. **R3.5 不预设方向**：V3.7 维持 / ML 反超 / 两者无统计区分，三者同为合法结论；
   结论一律以**配对差 HAC t** 表述（§0.3），禁止用两条 IC 各自 t 值大小比较。
4. **禁再调参**：S6.1/S6.2 的网格与邻域结果严禁反哺参数选择；那是过拟合陷阱。
5. **先登记后跑**：任何新机制/新变体须先在 `优化计划_V5_重规范_2026-09.md` 登记（预登记下一号 #39 起），
   冻结判定门后再执行；跑完只看数字，**禁事后改门**。

## 6. Windows CMD 详细步骤（逐条照抄即可）

> 假设：已安装 Git for Windows 与 Python 3.11（`python --version` 确认）。全程在 **命令提示符（cmd.exe）** 中操作，
> PowerShell 亦可（把 `set X=Y` 换成 `$env:X="Y"`）。**仓库路径不要含中文与空格**，避免 PyInstaller/编码坑。

### 7.1 取代码、建环境（一次性）

```bat
cd /d D:\code
git clone https://github.com/siyuan-yuan/quant_fund_picker.git
cd quant_fund_picker
git fetch origin arena/01a05f52-quant-fund-picker
git checkout -b arena/01a05f52-quant-fund-picker origin/arena/01a05f52-quant-fund-picker

run_local_batch.bat setup
```
> `setup` = 建 venv + 按 `requirements-v5-lock.txt` 钉版安装（pandas 3.0.5 / numpy 2.4.6 / sklearn 1.9.0 / statsmodels 0.15.0）。
> 若某个包装不上（Windows 缺 wheel），**不要**自行升降级——换 Python 3.11 x64 重试并回报，版本漂移会破坏跨机一致性。

### 7.2 跨机一致性闸门（必做，约 1 分钟）

```bat
run_local_batch.bat parity 4
```
它会跑 `build_navadj.py` 再逐项对账，输出形如：

```
项            权威值    本机值   判定
pool           4987     4987   PASS
events        21454    21454   PASS
kind_div      12090    12090   PASS
...
✅ D0.2 跨机对账全同（池/事件/分类/年化差），可继续下游
```
**任一 FAIL 就停机排查**（净值缓存是否 15,444 只、依赖是否钉版），不要继续。

### 7.3 数据（若 `cache/nav_*.csv` 不足 15,444 只）

```bat
run_local_batch.bat status            :: 先看 nav 数量
.venv_review\Scripts\python.exe t0_fetch.py --start 20060101 --end 20260331
```

### 7.4 规范面板（S6.1 汇总的前置，约 40 分钟，可中断续跑）

```bat
run_local_batch.bat base 2
```

### 7.5 S6.1（11 组面板，~12h CPU；6–8 路并行约 1.5–2.5h）

```bat
run_local_batch.bat s61 6

```

### 7.6 R3.5（动物园缓存 8 路并行约 20–40min + 主体）

### 7.9 Windows 常见坑

| 现象 | 处理 |
|---|---|
| 中文日志乱码 | 已在 bat 内 `chcp 65001` + `PYTHONIOENCODING=utf-8`；若仍乱码，检查控制台字体 |
| `ModuleNotFoundError` | 确认用的是 `.venv_review\Scripts\python.exe`，不是系统 `python` |
| 多进程起不来（`r35 --workers 8`） | Windows 用 spawn，启动较慢属正常；若报 pickling 错误就把 `--workers` 降到 1 并回报 |
| 杀进程后重跑 | 直接重跑同一条命令；按月/按组断点续跑，不会重算已完成部分 |
