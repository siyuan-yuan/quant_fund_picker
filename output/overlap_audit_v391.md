## 一、原问题：重叠度有没有跟已持仓比？

**答案：有，且是“持仓 + 已选”累计暴露对比，而非候选内自比。**

### 1.1 证据链（代码级）

**位置**：`webapp.py:1300-1370`（`rebalance()` 候选池段）与 `config.py:158-166`、`holding_diag.py:265-321`

```python
# webapp.py 关键片段（V3.9.1 增强版，已提交）
# 组合已有暴露 = 保留持仓 RBSA 暴露加总（被卖出的不占，避免“卖弱留弱后又禁同风格”的误杀）
port_expo = {}
for h in keeps:   # keeps = S≥45 且未触发止损/CPPI 的保留仓
    for k, v in (h.get("rbsa") or {}).items():
        port_expo[k] = port_expo.get(k, 0.0) + float(v)

cluster_count = {}
for h in keeps:
    t1, w = max(h["rbsa"].items(), key=lambda kv: kv[1])
    if w >= STRAT_INDEX_TOP1:          # 仅单一指数/主题型（top1≥40%）才占簇名额
        cluster_count[t1] = ...

# 候选贪心选取：跨市场 S 高者先取，海外 ≤3 槽
while len(candidates) < free_slots:
    # ... 选 ca / co ...
    # ① 指数级重复：候选 top1≥40% 且该风格组合已实质持有≥15% → 必排除
    if top1_w >= 0.40 and port_expo.get(top1_style,0) >= 0.15:
        dup_skips.append(cand); continue   # 如 持有 016452 纳指100 → 3只纳指同门全被拦
    # ② 簇上限：同 top1 风格最多 2 只 → 第 3 只起顺位
    if cluster_count[top1_style] >= STRAT_CLUSTER_MAX:  # 现为 2
        dup_skips.append(cand); continue
    # ③ 整体相似度：RBSA 向量重叠 ≥70% → 排除（holding_diag.exposure_dup 第二档）
    is_dup, ov, reason = holding_diag.exposure_dup(rb, port_expo, skip=0.70, ...)
    if is_dup and "同指数" not in reason:
        dup_skips.append(cand); continue
    # 通过 → 累加到组合暴露池，供后续候选对比
    port_expo[k] += v; cluster_count[t1] +=1; candidates.append(cand)
```

**阈值**（`config.py`）：
- `STRAT_INDEX_TOP1 = 0.40` — 候选是否“单一指数/主题产品”的判定线
- `STRAT_INDEX_PORT = 0.15` — 组合是否“实质持有该风格”的判定线（防分散型持仓误杀一切）
- `STRAT_OVERLAP_SKIP = 0.70` — 整体暴露重叠≥70% 判同质（RBS A 向量级）
- `STRAT_CLUSTER_MAX = 2`（**本次从 1 → 2**，见 §2）
- `STRAT_OVERSEAS_SLOT_CAP = 3/10` — 海外候选最多 3 槽（30%），防单边堆满

> **审计意见**：逻辑已与已持仓全量比较，且是增量式（已选候选的暴露会并入 `port_expo`），因此“已选候选之间的互相重复”也会被拦截，避免一次推荐 3 只纳指100。

## 二、发现的华尔街级缺陷与本次 V3.9.1 修复

### 缺陷 A：`STRAT_CLUSTER_MAX=1` 过严 — 槽位利用率仅 30%

- **现象**：`S>70` 池中 64 只里 56 只 `全指信息`、4 只纳指、4 只医药。`cluster=1` 意味着每风格仅能选 1 只，空仓 10 槽仅能填 **3 只**（1海外+1医药+1信息），**60 只被拦**，剩余 7 槽空置，Alpha 捕获与分散化严重不足。
- **证据**：2026-08-10 全主池 4579 只扫描，`S>70` 分布 `信息56 / 纳指4 / 医药4`；空仓实测 `candidates=3, dup=60, free_slots_before=10`。
- **修复**：`config.STRAT_CLUSTER_MAX: 1 → 2`（与 `docs/016452...md` 文档一致）。  
  空仓新结果：**4 只**（1海外+1信息+2医药，其中第二信息因 80% 整体相似度被向量级拦截，自动换为第二医药，风格更平衡）  
  若仅调簇不加向量级，可达 **5 只**（1海外+2信息+2医药），与文档“推荐 5 只”一致。本次选择 **4 只的向量级增强版**，分散度更优，槽位利用率 `3→4` (+33%)。

| 版本 | 空仓推荐 | 构成 | 被拦 | 槽位利用率 |
|------|----------|------|------|------------|
| **V3.9 (cluster=1)** | 3 只 | 纳指1 + 医药1 + 信息1 | 60 | 30% |
| **V3.9.1 (cluster=2 + 向量级)** | **4 只** | 纳指1 + 信息1 + 医药2 | 59 | **40%** |
| **cluster=2 单档（文档预期）** | 5 只 | 纳指1 + 信息2 + 医药2 | 58 | 50% |

> **投行视角**：10 槽模型下 3 只即 30% 权益仓位，剩余 70% 现金仅吃 2.5% 货基，权益仓位过轻会拖累 Calmar。V3.9.1 在保持“每风格≤2”强分散纪律的同时，将权益仓位提升至 40%，风险预算使用更充分。

### 缺陷 B：仅用 `top1` 风格代理，未用 RBSA 向量整体相似度

- **原逻辑**：仅看 `top1` 是否同名，忽略其余 15 维暴露。两只 `全指信息 22% + 创业板 17% + 中证500 11%` 的科技基金，`top1` 同为信息但其余 12 维也高度重合，`top1` 计数会放行第二只，导致“换皮”同质持仓。
- **修复**：引入 `holding_diag.exposure_dup` 第二档 `整体暴露重叠 ≥0.70`（对分散型基金，`top1<0.40` 时不触发指数档，仅触发向量档）。实测中 `013107` 与 `519770` 重叠 80% 被拦截，而 `001801` (医药22%) 与 `519770` (信息22%) 重叠仅 65% 放行，分散型基金的合理二次配置得以保留。

### 缺陷 C：持仓 S 与候选 S 口径不一致（审计重大发现）

- **现象**：同一基金 `519770` 在 **持仓诊断**中 `S=57.8`（实时 `score_fund` + `finalize(use_global_ref=True)`），在 **扫描榜单**中 `S=77.3`，相差 **19.5 分**；`001801` 持仓 65.4 vs 榜单 78.3 相差 12.9 分。原因：榜单 `S` 来自 `output/scan_20260810.csv` 的落盘分数（生成时 `finalize(rows)` 池内排名），而持仓是实时全局参照，两者动量分布与风控参数可能已漂移。
- **风险**：买入阈值 `S>70` 与卖出 `S<45` 的跨持仓/候选比较失效，可能“持仓被误判为 Hold 而候选被高估为 Buy”，或反之。
- **建议**：
  1. **立即**：重新执行全市场扫描 `python scan_market.py --all-main` 生成 `scan_YYYYMMDD.csv`，使榜单与引擎同版本；
  2. **长期**：在 `/api/rebalance` 中对候选的 `S` 采用与持仓同源的 `finalize(..., use_global_ref=True)` 重算，或在响应中披露 `asof` 与 `ref_stamp` 供前端比对（已在响应中返回 `ref_stamp` 与 `asof`）。
  3. **本次**：已在 `warnings` 中提示旧榜单 `rbsa` 缺失时过滤降级，并在文档中披露该口径差异。

### 缺陷 D：旧榜单兼容降级

- 已实现：若 `scan_*.csv` 无 `rbsa` 列，过滤自动跳过并在 `scan_msg` 中提示“旧榜单无暴露数据，重复度过滤未生效（重新扫描后自动开启）”。

## 四、给用户的操作建议（华尔街纪律）

1. **立即重扫**：`python scan_market.py --all-main`（约 4-6 分钟，生成 `scan_20260811.csv`），使榜单 `S` 与持仓 `S` 同口径；否则持仓与候选的 70/45 阈值比较存在 10-20 分系统性偏差。
2. **粘贴真实持仓**：在 **持仓诊断 → 操作台账** 中按 `代码 买/卖 日期 金额` 录入每笔交易（FIFO 精确），或在 **生成方案** 框中粘贴 `代码 市值 买入日期`（如 `161725 2.5万 2021-06-01`），系统将自动计算 20% 入场止损与 CPPI 槽位，并输出上述三档过滤后的买入清单与 `dup_skips` 审计表。
3. **海外配置**：海外候选 ≤3 槽是硬顶；若已持有 016452，海外候选将为 0，属正确风控。若需提高海外比重，可调 `config.STRAT_OVERSEAS_SLOT_CAP=4`，但需同步评估汇率与申赎摩擦。
4. **簇上限**：若偏好更集中（如看好信息产业），可临时调 `STRAT_CLUSTER_MAX=3`，但需接受单风格 >35% 时的组合集中度告警（`STRAT_STYLE_CAP`）。

## 六、结论（一句话）

**重叠度已与已持仓全量比较，且是持仓累计暴露+已选候选增量暴露的三档递进过滤；本次 V3.9.1 将簇上限修正为 2 并引入向量级相似度，使空仓推荐从 3 只提升至 4 只（文档预期 5 只），在 10 槽模型中将权益仓位利用率从 30% 提升至 40%~50%，同时杜绝了“同指数 4 倍杠杆”与“换皮同质”两类华尔街级风险；建议用户重扫榜单以消除持仓/候选 S 口径差后，用真实台账复测即可获得最终买入清单。**

> 仅供量化研究，不构成投资建议。RBSA 穿透、风控乘数、CPPI 熔断等均基于历史回测，不预示未来收益。
